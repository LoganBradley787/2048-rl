# 2048 — Python backend + web UI + trainable environment

Date: 2026-09-15

## Goal

A 2048 game whose rules and state live entirely in Python, so that:

1. A human can play it in a browser.
2. A neural network can be trained against the same code with no HTTP in the loop.
3. A trained policy can be plugged in and watched playing in the browser.

## Components

### `game2048/core.py` — the rules (no dependencies)

- `Direction` int enum: `UP=0, RIGHT=1, DOWN=2, LEFT=3`. These are the action indices everywhere.
- `Game(size=4, seed=None)` holds `board` (list of lists of ints, 0 = empty), `score`, and a private `random.Random`.
- `reset()` clears the board, score, and spawns two tiles.
- `move(direction) -> MoveResult(moved: bool, reward: int)`. Slides and merges in the standard way (each tile merges at most once per move, merges happen toward the move direction). If the board changed, a new tile spawns (2 with p=0.9, 4 with p=0.1) in a uniformly random empty cell and `score += reward`. If nothing changed, no spawn and `reward = 0`.
- `legal_moves() -> list[Direction]` — directions that would change the board.
- `is_over()` — no legal moves.
- `max_tile()`, `clone()`, `to_dict()`, `from_dict()`.
- Pure helper `slide_and_merge_row(row) -> (new_row, reward)` for left-merge; other directions are built by transposing/reversing.

### `game2048/env.py` — training wrapper

- `Env2048(size=4, seed=None, invalid_move_penalty=0.0, max_invalid_moves=None)`.
- `reset() -> obs`; `step(action) -> (obs, reward, done, info)`.
- `obs` is a flat list of `size*size` ints, each `log2(tile)` (0 for empty). `obs_array()` returns the same as a numpy array; numpy is imported lazily so core stays dependency-free.
- `action_mask() -> list[bool]` of length 4.
- `info` includes `moved`, `score`, `max_tile`, `legal_moves`.
- Invalid moves return `reward = -invalid_move_penalty`, `done` stays False unless `max_invalid_moves` consecutive invalid moves is reached.

### `game2048/agents.py`

- `Agent` protocol: `act(game: Game) -> Direction`.
- `RandomAgent(seed)` picks uniformly among legal moves.
- `GreedyAgent` picks the legal move with the highest immediate reward, ties broken by fewest tiles left.
- `AGENTS` registry dict `name -> factory` used by the server. A trained network is added by registering a class here.

### `game2048/server.py` — FastAPI

- One `Game` per process, guarded by a `threading.Lock`.
- `GET /api/state` → `{board, score, over, legal_moves, max_tile}`.
- `POST /api/move` body `{direction: int|str}` → state plus `{moved, reward}`. Bad direction → 422.
- `POST /api/new` body `{seed?: int}` → fresh state.
- `POST /api/agent/step` body `{agent: str}` → applies one move from the named agent; unknown agent → 404; game over → 409.
- `GET /api/agents` → list of registered agent names.
- `GET /` serves `static/index.html`; `/static/*` mounted.

### `static/` — UI

Plain HTML/CSS/JS, no build step. Renders the board from `/api/state`, sends arrow-key / WASD presses as `/api/move`, shows score and a localStorage best score, game-over overlay, buttons for New Game, Agent Step, and Auto-play (loops `/api/agent/step` at a fixed interval), and a dropdown of agents from `/api/agents`.

## Testing

- `tests/test_core.py`: row merge cases (no double merge, gaps, ordering), each direction, spawn probabilities, `legal_moves`, `is_over`, determinism under seed, `clone` isolation.
- `tests/test_env.py`: obs encoding, reward passthrough, mask, invalid-move handling, episode termination.
- `tests/test_server.py`: every endpoint with FastAPI's `TestClient`.

## Training (added later the same day)

### `game2048/vec_env.py`

numpy engine over `(N, 4, 4)` uint8 boards of exponents. A 65536-entry lookup
table maps each row (four nibbles) to its left-slid row and reward; other
directions reverse or transpose first. `afterstates()` returns all four moves
at once. `VecEnv` keeps N boards, resets by mask, and spawns tiles with the
same 90/10 rule. Eight symmetry helpers cover the dihedral group. Equivalence
with `core.Game` is tested on random boards for every direction.

### `game2048/nn.py`

`ValueNet`: one-hot (16 channels) -> Conv2d 2x2 (128) -> Conv2d 2x2 (128) ->
Linear 512 -> Linear 1. `greedy_actions()` picks argmax over legal moves of
reward*scale + V(afterstate). `NNAgent` loads `checkpoints/best.pt` (or
`GAME2048_CHECKPOINT`) and is registered as "nn". Averaging over the eight
symmetries is on by default at play time.

### `game2048/train.py`

Afterstate TD(0): 512 parallel boards, greedy action selection with the
online net, replay buffer of (afterstate, scaled reward, next afterstate,
done), target network with Polyak averaging, Huber loss on reward + V_target
(next afterstate) with 0 at game end, random symmetry augmentation on inputs.
Rewards are scaled by 1/2048. Periodic evaluation over 200 fixed-seed games
writes `log.csv` and saves `best.pt` / `latest.pt`.

## Tile modes (added later the same day)

`Game(spawn_mode=...)` with `random` (standard), `kind` (never a placement
that ends the game while another keeps a move; the drawn value is tried
first, then the other), `best` and `evil` (the placement that maximises or
minimises the player's best reply, reward plus `evaluator(afterstate)`; a
placement with no reply counts as minus infinity, so best never ends the
game when avoidable and evil always does). The evaluator defaults to
`core.heuristic_value`; the server uses `evaluators.best_available()`, the
n-tuple tables when trained. `mode` is in the state dict, `POST /api/new`
takes it, `GET /api/modes` lists it, the UI has a selector. `Env2048` passes
it through; `VecEnv` implements `random` and `kind` (vectorised safety check
of every candidate placement); the CNN trainer's `Config.spawn_mode` selects
it. The C engine keeps random spawns.

## Native n-tuple player (added later the same day)

### `game2048/native/ntuple.c`

- Bitboard: uint64, cell i in nibble i (row-major), exponent values. Row
  lookup tables for left/right, transpose for up/down. Same merge rule as
  `core.py`, with the 2^15 cap of `vec_env.py`. Tested for exact agreement.
- Network: K patterns (default four 6-cell patterns), each sampled under the
  8 symmetries; float32 tables of 16^n entries. V(board) is the sum of the
  8K looked-up weights. Multi-stage: optional tile-mass boundaries select a
  separate table set; an entry a later stage never touched reads through to
  the previous stage (weight promotion).
- Learning: afterstate TD(0). Temporal coherence (per-weight rate |E|/A) by
  default, plain TD with `--no-tc`. Games are distributed to threads via an
  atomic counter and threads update the shared tables without locks.
- Search: expectimax over moves (max) and spawns (expectation over empty
  cells, 2 at 0.9 / 4 at 0.1), leaves scored by V, transposition table keyed
  by (afterstate, depth), optional probability cutoff. `depth` = spawn layers.
- Persistence: `NTUPLE03` files (older 01/02 still load) with header,
  boundaries, patterns, then per-stage tables (weights, and E/A when the
  learning state is kept). `weights_only` saves drop E/A and bake stage
  promotion in. A single-stage file can be loaded as stage 0 of a
  multi-stage network. `nt_lock_memory` pins all tables with mlock.

### `game2048/ntuple.py`, `game2048/ntuple_train.py`

ctypes wrapper that builds the library on demand; `NTupleNet` (train, play,
value, best_move, save/load), `NTupleAgent` registered as "ntuple" (depth 3
by default), and a resumable training CLI writing `log.csv` (per chunk of
training games) and `eval.csv` (expectimax evaluations).

## Out of scope

Multiple concurrent games per server, undo, persistence, and search-time
extensions such as adaptive depth by empty-cell count or a per-move time
budget.
